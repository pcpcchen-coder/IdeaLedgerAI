Idea Ledger v2：帳號層巡檢設計

設計文件 v2.1 · 2026-10-15 · 取代 v1 的「各瀏覽器即時擷取」為主線；v2.1 新增平台開放擴充（第 11 節）

一句話：一台常開的電腦（建議 Mac Mini）上，用一個專用 Chrome 設定檔登入 ChatGPT、Claude、Kimi；擴充每 30 分鐘以你的登入狀態讀取各平台的對話歷史，把新增或有更新的對話送給本機 collector，由本地模型摘要成想法卡。
  • 網頁、桌面 App、手機 App 的對話都會同步到帳號，所以全部涵蓋。
  • 只讀取，不對平台做任何寫入；對話中零痕跡。
  • 公司電腦不用裝任何東西，collector 只聽本機，不必對外開放。

1. 與 v1 的差異

2.1 為什麼讀取要在平台分頁裡執行

讀取請求由該平台網域上的 content script 發出（同源請求），而不是由擴充背景直接打。原因：

  • 同源請求自然帶上登入 cookie，不受 SameSite 限制。
  • 行為與你正常瀏覽一致，較不易觸發 Cloudflare 等機器人防護。
  • 需要的權杖（例如 ChatGPT 的 access token）可在同源下取得。

背景若找不到某平台的分頁，就開一個釘選、非作用中的分頁並保持開著。

3. 平台 Adapter

平台差異全部封裝在 extension/adapters/<platform>.js，對外介面固定：

// 每個 adapter 都實作這 3 個函式，在該平台網域的分頁內執行
async function checkLogin()                 // → { ok: true } | { ok: false, reason }
async function listUpdated(sinceIso, limit) // → [{ id, title, updated_at }]，依 updated_at 由新到舊
async function getConversation(id)          // → NormalizedConversation（見 4.1）
平台讀取方式（非官方，實作時以 DevTools Network 驗證）待驗證
ChatGPT先取 session 的 access token，再讀對話清單與單篇對話；單篇是樹狀結構，從目前節點往回走取得使用中的分支專案（Projects）裡的對話可能不在主清單，需另外列舉
Claude先取組織 ID，再讀該組織的對話清單與單篇對話；依目前葉節點取使用中的分支Projects 內對話是否在同一清單
Kimi介面未知，實作第一步就是在 DevTools 觀察歷史清單如何載入App 對話是否同步到網頁歷史；若無可用介面，退回 v1 的頁面文字擷取

4. 資料規格

4.1 擴充送往 collector 的格式

POST http://127.0.0.1:8787/v2/conversations
Authorization: Bearer <token>

{
  "platform": "chatgpt",              // 平台 id，由 adapter 的 platform.json 定義，不限定清單
  "platform_name": "ChatGPT",         // 顯示名稱（選填）
  "capture": "api",                   // api：帳號層巡檢；page：免程式平台的頁面文字擷取
  "conv_id": "6710c2e4-...",
  "title": "換電站排程想法",
  "url": "https://chatgpt.com/c/6710c2e4-...",
  "project": "換電站EMS系統",           // 平台上的專案名稱，沒有則 null
  "created_at": "2026-10-15T01:12:00Z",
  "updated_at": "2026-10-15T02:40:00Z",
  "messages": [
    { "role": "user",      "text": "...", "at": "2026-10-15T01:12:00Z" },
    { "role": "assistant", "text": "...", "at": "2026-10-15T01:12:30Z" }
  ],
  "swept_at": "2026-10-15T03:00:00Z",
  "sweeper": "mac-mini"                // 哪個節點抓的，方便除錯
}

只保留使用中的分支；圖片、檔案只記檔名，不傳內容。

4.2 Collector 資料表

conv(platform, conv_id, title, url, project, created_at, updated_at,
     messages_json, message_count,
     summarized_count,      -- 已摘要到第幾則，供增量摘要
     dirty,                 -- updated_at 變大時設 1
     PRIMARY KEY(platform, conv_id))

sweep_run(platform, started_at, finished_at, status, listed, fetched, error)
          -- 每輪巡檢一筆，供健康監控

冪等：同一 (platform, conv_id, updated_at) 重送不會重複處理，所以多台電腦同時巡檢也不會出錯。

5. 巡檢演算法

  1. 排程：chrome.alarms 每 30 分鐘觸發，加 0–5 分鐘隨機延遲。
  2. 逐平台依序處理，不平行：
    1. 確認平台分頁存在且未被休眠（被 Chrome 省記憶體機制丟棄就重新載入）。
    2. checkLogin()；失敗則標記該平台為「需重新登入」，跳過。
    3. listUpdated(watermark)，分頁往下讀，直到遇到 updated_at ≤ watermark 為止。
    4. 略過 10 分鐘內仍在更新的對話（可能還在聊），留給下一輪。
    5. 逐篇 getConversation()，送 collector；成功才前移 watermark。
  3. 寫入 sweep_run，更新擴充圖示狀態。

5.1 節流規則

規則值理由
巡檢間隔30 分鐘（可調 15–120）延遲與負載的平衡
請求間隔每次請求間隔至少 3 秒接近人工翻閱的頻率
每輪單篇讀取上限每平台 30 篇回填時不暴衝，下一輪接續
遇到 429／403該平台暫停，退避 1→2→4→8 小時避免被封鎖
只用讀取請求僅 GET，絕不寫入不改動任何平台資料

5.2 首次回填

watermark 初始為空，巡檢會沿用上述上限一路往回讀完全部歷史。以每輪 30 篇、每 30 分鐘計算，1,000 篇約需 17 小時，可接受。想更快就改用官方匯出（ChatGPT、Claude 皆有）一次匯入，再把 watermark 設為匯出時間。

6. 排除規則

  • 臨時對話：ChatGPT 臨時對話、Claude 無痕對話本來就不進歷史，自然不會被抓。
  • #nolog：第一則使用者訊息含 #nolog 的對話，collector 直接丟棄、不落地。
  • 專案黑名單：設定頁可列出不想記錄的平台專案名稱（例如特定公司專案），整個略過。

7. 健康監控（無人看管必備）

狀態條件呈現
正常最近一輪成功擴充圖示綠點
退避中遇到 429／403黃點，顯示恢復時間
需重新登入登入檢查失敗紅點；每日日誌頂端列出
介面失效回應格式不符 adapter 預期紅點；需更新 adapter

每日日誌 Ideas/_log/YYYY-MM-DD.md 第一行固定寫各平台巡檢狀態，你翻日誌就知道系統是否健康。任一平台連續 24 小時失敗，collector 發一則 macOS 通知。

8. 產出（與 v1 相同，資訊更完整）

  • 想法卡：Ideas/YYYY/MM/YYYY-MM-DD_<platform>_<標題>.md，frontmatter 新增 project（平台上的專案名稱）。
  • 每日平台互動日誌：依對話的實際更新時間（不是巡檢時間）歸到當天，所以補抓的舊對話會出現在正確日期。
  • 可回答的問題：哪天跟哪個平台聊了什麼、某個想法最早在哪個平台出現。
  • 無法回答：是在網頁還是 App 上聊的，各平台歷史介面通常不提供這項資訊。

9. 部署（Mac Mini）

  1. 建立 Chrome 專用設定檔「IdeaLedger」，登入三個平台。
  2. 載入擴充（未封裝），設定 collector 位址與 token；巡檢模式開啟。
  3. Chrome 設定把三個平台網域加入「一律保持作用中的網站」，避免分頁被休眠。
  4. 系統設定：禁止睡眠；登入項目加入以該設定檔啟動 Chrome。
  5. docker compose up -d 啟動 collector（只綁 127.0.0.1）；launchd 註冊 summarizer。
  6. 驗收：三個平台各在手機 App 聊一段，1 小時內應出現想法卡。

也可以裝在你日常用的瀏覽器上，但電腦闔上就停擺，因此建議 Mac Mini 當主節點。

10. 風險

風險影響對策
非官方介面改版該平台停止收集adapter 隔離，只改一個檔；格式檢查失敗立即紅燈；Kimi 保留頁面文字退路
服務條款灰色地帶理論上帳號受限只讀自己的資料、低頻、僅 GET、遇 429 立即退避
登入過期收集中斷紅燈 + 日誌 + 24 小時通知，手動重登一次
專用設定檔握有三個帳號的登入Mac Mini 被入侵即外洩Mac Mini 設登入密碼、FileVault；collector 只綁本機
多台同時巡檢重複請求collector 冪等；建議只開一個主節點

11. 平台開放擴充（v2.1 新增）

ChatGPT、Claude 只是內建的前兩個平台。使用者日後要加入 Gemini、Grok 或其他網頁版 AI，都不需要修改核心程式。

方式一：寫 adapter方式二：設定頁新增（免程式）
做法新增 extension/src/adapters/<id>/：platform.json（id、name、hosts）＋ 解析層 ＋ 取資料層設定頁填名稱、網域、對話網址規則
註冊建置時自動掃描資料夾，產生註冊表與 manifest 網域權限執行時向使用者要網域權限，動態注入擷取腳本
收集範圍帳號歷史全部，含手機 App只有在這個瀏覽器打開過的對話
資料形式結構化訊息（capture="api"）頁面純文字（capture="page"）

為了讓兩種方式都成立，整條管線只認平台 id 的格式（小寫英數與連字號），不維護平台清單：collector 不做 enum 檢查、摘要與 Obsidian 寫入以 id 與顯示名稱處理。方式二可以先用，之後寫好 adapter 再升級，同一個 id 沿用，歷史資料不中斷。操作說明見 repo 的 docs/ADDING_A_PLATFORM.md。
